# CLAUDE.md — `src/lib/plotting`

Detail on the rendering layer: turning `PlotTarget`s into a matplotlib figure that can be re-driven each animation frame. The pipeline overview and `var_infos` live in the repo-root `CLAUDE.md`; `PlotTarget` itself is documented in `src/lib/data/CLAUDE.md`.

## PlotInfo, Renderer, and figure assembly (Grid / Panel / setters)

**`Renderer[D, SD, PI]`** (`src/lib/plotting/renderer.py`) — *data → `PlotInfo`*. Constructed from a single `PlotTarget` (it reads `plot_target.data`; nothing is passed in separately), generic over the data type, spatial-dims type, and plot-info type. `__init__` calls `_init_plot_info()`; `_get_data_at_frame(frame)` applies `Idx({time_dim: frame})` to slice one frame; `get_n_frames()` is the length of the time coord (1 if no `time_dim`). The concrete subclasses live in `src/lib/plotting/renderers/` (`field_1d` / `field_2d` / `polar_field` / `scatter`).

`PlotInfo` (`src/lib/plotting/plot_info.py`) describes *what* to draw: data arrays, per-dim `dim_scales` / `dim_bounds` / `dim_displays` / `dim_units`, `subject_dim` (the dim that *is* the plotted variable: `y_dim` for a 1D field, `color_dim` for 2D/polar, `None` for scatter), `scalar_coord_values` (for labels), `axes_index`, and `projection`. It is a **plain mutable dataclass** — `update_plot_info(frame)` just assigns fields; propagation to matplotlib is a separate pull step. Mixins declare which axes a shape has: `PlotInfo2D` (`x_dim`/`y_dim`), `PlotInfoColor` (`color_dim`), `PlotInfoMaybeColor` (optional `color_dim`); concrete shapes are `LineInfo` / `ImageInfo` / `ScatterInfo` / `PolarMeshInfo`. `has_legend()` / `has_colorbar()` are what drive the wiring below.

`setup_fig(plot_infos, options)` (`src/lib/plotting/setup_fig.py`) is called once from `Plot._initialize()` and returns `(Figure, Grid)`, with nothing placed yet: `Plot._initialize()` runs the hooks' `post_init_fig`, then `run_layout` (see *The layout engine* below), then `update_ticks()`. Anything that adds to the figure must come before `run_layout`.

- **`Grid`** (`grid.py`) groups infos by `axes_index`, adds one axes per location (rejecting mixed `projection`s), and owns a `Panel` per location plus the figure suptitle labeler. `setup_fig` builds every panel, then `share_x_axes_vertically` (stacks), then `arrange_colorbars` (y sharing and colorbars, decided together), then the inward ticks. `Grid.update()` (every frame) = `update_data()` → `update_bounds()` → `update_ticks()` → `update_labels()`; none of it measures anything, so it never moves a plot area.
- **`Panel`** (`panel.py`) holds everything attached to one axes location: data setters, per-axis dicts of bounds setters and scales (keyed by `(Axes, AxId)`, so a twinned right-hand axis is just another key), and x/y axis labelers keyed by `Axes`. It is built through `wire_*` methods, each paired with a `can_wire_*` predicate that tests compatibility *before* committing.
- **`setup_panel_xy`** (`setup_fig.py`) is the placement algorithm. It sorts infos so legend-capable ones come last, then for each info wires the x-axis (incompatible → hard error) and tries the left y-axis; if that fails and the info has a legend, it twins a right y-axis and tries again. There is no per-shape dispatch and no image-vs-line special case — placement is decided purely by unit/scale compatibility.
- **`DataSetter`** (`data_setter.py`) holds an artist + its info; `DataSetter.dispatch_init(ax, info)` picks `LineSetter` / `ImageSetter` / `ScatterSetter` / `PolarMeshSetter`, and `update()` pushes info → artist.
- **`BoundsSetter`** (`bounds_setter.py`) holds every info sharing one axis and sets the widest of their bounds, skipping the matplotlib call when unchanged.
- **`AxId`** (`axis_id.py`) is the `"x" | "y" | "r"` literal that keys all the per-axis dicts.

**Animation loop** (`AnimatedPlot._next_frame`): every `Renderer.update_plot_info(frame)` runs first, then `Grid.update()`. So adding a new animatable property means (a) assigning it in `update_plot_info` and (b) reading it in the corresponding setter's `update()` — nothing else wires them together.

## The layout engine (`layout/`)

matplotlib's own layouts are not used. `layout/engine.py`'s `run_layout` places every plot area and colorbar **once per figure**, in plain inches: measure how far each panel's decorations (tick labels, axis labels, title, twin) reach past its plot area (`layout/measure.py`), take each row's and column's largest, size the plot areas, and stack it all up (`compute_layout` → `Layout`, applied by `apply_layout`). Tick labels depend on the sizes, so it repeats measure → place (`MAX_LAYOUT_PASSES`) until nothing moves; each pass runs `Grid.adjust_to_draw()` (thin crowded ticks, draw, tuck end labels, separate junction labels, colorbar bottom texts), the only steps that measure drawn text. Every text is set to its **widest string over all frames** for the passes (`widest_frame_texts`), then restored to frame 0's, so no frame needs more room than it got and movies never shift.

- **Sizes** (`layout/auto_size.py`): `auto_plot_sizes` gives each panel its auto size: a default area; equal-scale panels (x and y in the same unit) keep that scale, and share **one inches-per-unit across the figure per unit**, so same-extent panels come out the same size; images get at least `MIN_DOTS_PER_CELL` dots per cell. A fixed `--figsize` side is split in proportion to the auto sizes. Plot areas grow until two tick labels fit on every axis and colorbar (`two_label_length`), never below `MIN_PLOT_SIDE`; a fixed side too small for that warns and enlarges.
- **Sharing is decided from sizes first.** Plot edges line up across the whole grid, so a row (column) boundary is **flush** only if every column (row) with panels on both sides can share there and the auto sizes already match (`Grid.flush_row_boundaries` / `flush_col_boundaries`). Flush panels' facing margins are zero; a panel narrower than its column hugs its flush neighbor.
  - Stacks (`Panel.share_x_axis`): the upper panel loses its x tick labels and both titles go (their labelers' children move to the suptitle).
  - Side by side (`Panel.share_y_axis`): sharey, the right panel's y tick labels hidden, the labelers merged.
  - Either way the panels' **bounds setters are merged**, so the shared axis covers both panels' data.
- **Colorbars** (`layout/colorbars.py`, pure, on a `GridModel`): `assign_colorbars` decides which colorbars exist and which images each keys, together with which column boundaries are flush, since they constrain each other. Images share a bar when their color dim's display, unit and scale agree (`Panel.color_key`; an untitled panel also needs the same coord values on every frame, since only the bar's label can say them). A vertical bar keys its run of flush panels to its left, extended down same-key runs flush below; a row that shares y but not one bar gets a horizontal bar above each image (never inside a stack). Every image is keyed exactly once, and no bar sits in a junction other rows/columns hold flush; if sharing y everywhere would break that, no column is flush. `Grid.arrange_colorbars` applies the plan: one `Colorbar` per assignment, owned by its first anchor's panel (`Panel.colorbars` / `colorbar_assignments`), color limits unified (`plt_util.update_shared_cbar`). The engine spans extended bars over their anchors and raises a panel's title over a horizontal bar (`Layout.title_offsets`).
- **Ticks** (`ticks.py`): `InwardTicks` draws inward ticks on every side of a plot area and both long sides of a colorbar as **separate scatter artists** (matplotlib points an edge's ticks one way, in one color), each colored by `plt_util.get_contrasting_color` against what's beneath it (`DataSetter.get_colors_within`; a colorbar's colormap). The axes' own ticks have zero length. Use `set_offset_transform` for their positions; `set_transform` would scale the markers too.
- **Tick labels** (`tick_labels.py`): end labels are tucked inside their axes' span; crowded axes ask their locator for fewer ticks (restarting from the original density each pass, never below two in view) and hide what still overlaps (`_HIDDEN_LABELS`, so a later pass can restore them). Where flush axes meet, the second's end label is hidden only if it actually crowds the first's.
- **Twins**: the twin shares the left axes' color cycle, and an axis whose lines are all one color gets its label and tick labels in that color.

Rules learned the hard way:
- **Pin anything positioned from a measurement in fixed units** (points or inches, e.g. `transAxes + ScaledTranslation`), never as a fraction of an axes' size; the next pass can resize the axes. Colorbar texts hang off the bar this way.
- **Anything that mustn't take room must be out of layout** (`set_in_layout(False)`), e.g. the inward ticks: measuring uses tight bboxes.
- **Check movies, not just stills**: bugs from measuring per frame only show when frames are compared. Render the same layout as both a PNG (`-i t=…`) and an MP4, and compare extracted frames (`ffmpeg -i f.mp4 -frames:v 1 f0.png`, or `-vf "select='eq(n\,50)'" -fps_mode passthrough`), e.g. by checking that the axes spines land on the same pixel columns.

## Labels (Labeler)

`src/lib/plotting/labeler.py` owns all figure text. `Labeler` is just a wrapper around a `set_text` callable.

- **`SubjectLabeler`** — text describing *which data* is shown: an optional **subject** + any number of **sublabels** (scalar coordinate values, e.g. `y = 1.000`). These form a tree of label sites — figure suptitle above axes titles above y axes / colorbars above legend entries. A node with a `source` `PlotInfo` is a leaf and reads its labels from it; any other node factors out what **all** its children have in common. `update()` walks to the root, which `_rebuild()`s bottom-up.
  - A parent sees a child only through `_get_liftable_subject` / `_get_liftable_sublabels` and factors it out with `_lift_subject` / `_lift_sublabels`; subclasses override these, and the parent never special-cases a subclass. Children whose `_labels_any_data()` is false (e.g. a y axis holding only an image) are ignored, so they don't block their siblings. A `None` subject is never lifted, since a forwarding node would pass the lift to children with differing subjects.
  - `subject` is `PlotInfo.subject`: the display of `subject_dim`, **without its unit**; for scatter, `ScatterInfo.list_subject`.
  - Lifting is decided **by dim, from every frame** (`PlotInfo.frames_scalar_coord_values`, filled at init from `Renderer.get_scalar_coord_values`, which never computes data): a sublabel lifts only if every child has the same text on every frame, so labels never move between frames. The decision is cached (`_decided`) and redone when the tree changes.
- **`YAxisLabeler`** — a y axis's `display [unit]`, via a wrapped `UnitLabeler(require_display_match=False)`. Its children are the legend entries of lines whose `subject_dim` is their `y_dim` (other legend entries hang off the title). When the axis shows a display, that *is* their subject, so it **absorbs** it from them and the subject appears only on the axis. Otherwise it's transparent: it offers, and forwards lifts of, whatever its children have in common.
- **`ColorbarLabeler`** — a leaf for an image's colorbar label, when its `color_dim` is the `subject_dim`: `subject (sublabels)`, unit on the next line (`one_line` for horizontal bars). It never offers its subject, so the title gets only the sublabels. Each keyed image has one in its own panel's tree (the suptitle's if the panel has no title), reporting to the bar's **`SharedColorbarLabel`**, which shows their text if they agree, else just display and unit.
- **`UnitLabeler`** — plain axis/colorbar text (`display [unit]`): x axes, and colorbars not of the subject (e.g. scatter color). It holds several sources and raises if they disagree on unit (or on display, if `require_display_match`). An empty display (e.g. a `--fit` curve's) is unnamed and defers to the other sources, so it neither blanks the label nor counts as a disagreement. `is_compatible(info)` is a trial append/rollback — that's what `Panel.can_wire_unit_labeler_xy` uses to decide left-vs-right y-axis.

`Grid` wires the suptitle only once a second panel appears; stacking panels removes their titles, reparenting their children to the suptitle.

Text is 1.5× matplotlib's default size (legends 1.25×; tick labels and colorbar multipliers stay default), via `style.scaled_font_size`. Labelers are driven by `Grid.update_labels()` each animation frame. `Panel.update_labels()` also adds/removes the axes legend depending on whether any label text survived factoring.

## Hooks

Hooks (`src/lib/plotting/hooks/`) — currently `--grid`, `--vline`, `--show-com`, `--contour` — subclass `Hook` (`src/lib/plotting/hook.py`) and implement `post_init_fig(message)` / `post_update_fig(message)`, receiving a `DrawMessage(plot_info, axes, frame_data)`. `PlotPipeline.run_plot` (`src/lib/run/plot_pipeline.py`) attaches them and `Plot._initialize()` calls `post_init_fig` after building the figure. **Currently hooks are applied to the first renderer/axes only** — see the TODO in `plot.py`.
